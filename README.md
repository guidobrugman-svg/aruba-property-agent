# Aruba Property Agent

Monitors publicly advertised Aruba homes, villas, townhouses, land, and whole multi-unit residential properties offered for sale at no more than USD 800,000. Individual apartments/condos, rentals, unavailable listings, commercial buildings, timeshares, and construction-only modular-home offers are excluded.

## Monitoring

GitHub Actions requests a run every five minutes. GitHub schedules can be delayed; this is a best-effort polling interval, not a five-minute delivery guarantee. Every hour, the same job upgrades to a deep scan using the same permanent property history. Four workers check separate sources concurrently. Per-source limits, short HTTP timeouts, one transient retry, and persistent failure cooldowns prevent one broker from stalling the job. A changed collector configuration invalidates its old cooldown so a repaired source is retried immediately. Pagination follows advertised links or explicitly verified source endpoints. Repeated listing pages are detected and reported as partial coverage.

`SOURCES.json` contains selectors, category endpoints, and fast/deep page budgets. There are 19 configured websites (17 direct brokers and two aggregators). The six newly added direct brokers are Berkshire Hathaway Aruba, Realty ONE Group Aruba, HKG Real Estate Aruba, MPG Aruba, Aruba Happy Homes, and Objective Realty Aruba. Smiley uses its advertised read-only public listing-query POST API with USD currency, including explicit sold/unit filtering. Home 4 Everyone uses the advertised sale category and its pagination. MPG uses its advertised maximum-price filter and page controls. Aruba Listings uses listing-specific structured map data. Site access varies by network; a successful local test does not imply GitHub runner access.

## Events, history, and migration

Existing history keys and first-detected dates are retained. URLs from alternate brokers/aggregators become aliases; changes to type, price, or source do not define identity. Separate numbered lots are not automatically merged. Development consolidation requires an explicit project identity; this intentionally favors avoiding false merges.

A source’s first successful deep check baselines newly uncovered inventory rather than labeling it NEW. Earlier shallow checks also suppress historical discoveries, so later pages from that first deep scan do not flood the inbox. Coldwell Banker’s advertised public updated-listing RSS feeds are checked in the fast layer.

The first upgraded run establishes a baseline for newly uncovered inventory without generating historical NEW alerts. It archives the old unsent short-alert queues in `legacy_queues` for audit rather than releasing a backlog of potentially misclassified listings. All old history and daily activity remain in state. Subsequent runs detect new opportunities. A source/parser switch establishes a new price baseline instead of reporting a reduction. Same-source price reductions and major field changes need two agreeing successful observations. All observations matching one permanent historical identity are consolidated before change detection; conflicting aliases cannot confirm a change twice in one scan. Missing listings on shallow/failed scans remain in permanent history; only explicit unavailable status at the currently selected URL changes availability. A sold alternate URL cannot repeatedly toggle an active listing. The daily count includes available qualifying records seen in the past seven days, so it is an approximate recent monitoring count, not a claim that every historical listing is still available.

## Email

Resend, the existing verified sender, recipient, and `RESEND_API_KEY` are preserved. New-listing emails are queued immediately after detection. Confirmed reductions/major changes are batched after 30 minutes. This may increase email frequency compared with batching every event. GitHub commits discoveries and frozen outbox payloads before sending; accepted-email acknowledgements are committed afterward. Retries reuse the same payload and Resend idempotency key. Resend acceptance is not proof of inbox delivery; an ambiguous failure retried after Resend's 24-hour idempotency retention can still duplicate a message.

Daily digests target 08:00 Aruba (12:00 UTC). A delayed run catches up later the same local day. Digests contain activity since the last successfully sent digest and an approximate monitoring count, never a full inventory dump. Digest activity clears only after API acceptance. The email footer links to the GitHub monitoring workflow; disable it there to stop alerts. No hosted unsubscribe service is added.

## Test and investigate

```sh
python -m pip install -r requirements.txt
python -m unittest discover -s tests -v
DRY_RUN=1 python tools/validate_live.py deep
```

The validator uses temporary state copies, never production state or email credentials. It measures live coverage, preserves all history keys, and replays identical inventory to check false NEW events. It writes aggregate coverage and replay diagnostics to `live-validation.json` locally and the verification workflow uploads it as an artifact. `SCAN_MODE=fast|deep|auto` overrides cadence for investigation. `STATE_FILE` chooses a separate state file. `DEFER_DELIVERY=1` checkpoints without sending; `DELIVER_ONLY=1` processes a previously checkpointed outbox. Never run production state experiments against `state.json`.

Production workflow concurrency serializes monitoring. The verification workflow runs on this development branch and pull requests with read-only repository permission and no Resend secret. Review the PR and its validation evidence before merging; scheduled production behavior changes only after merge.

The owner's current preference retains standalone new-build projects but excludes residence-complex offerings (explicit `Residences` or `residence complex/development/project` evidence). A completed standalone residence is not excluded merely for using the singular word residence. This is a listing-language filter, not confirmation of zoning or permission to add apartments.

Emails show location, building/built-up area, and land area separately. Card-specific Houzez `.h-area` and `.h-land-area` fields and explicitly labeled areas are used; an unlabeled area is never presented as building area. Source `1 m²` placeholders are withheld. Land has no bedroom/bathroom counts or building area. Missing location, building area, and image are stated explicitly. Lazy-loaded listing photos take priority over inline data-image placeholders; email clients may still block remote images.

Development checks quote listing evidence for ownership, zoning, building restrictions, and apartment construction, with source links. No field becomes an inferred permission to build. Missing evidence is explicitly unknown. Detail enrichment rotates through at most two property pages per fast scan and four per deep scan, using four workers and existing bounded HTTP retries. Successful detail reads are cached for seven days; failures for one day. Only recognized property-specific sections contribute claims; related listings and navigation are removed. Detail failures cannot stop monitoring. These detail reads can also fill missing photos, addresses, and explicitly labeled areas, and identify residence-complex offerings beyond card titles. Live validation reports detail-reading time separately and replays frozen results.

## Coverage limits

This configuration does not cover the whole Aruba market. Public access and advertised card fields vary. RE/MAX Aruba, RES Aruba Realty, and Aruba Listings currently return access challenges on GitHub; Aruba Happy Realty has a hostname/certificate error. TLS checks stay enabled. They remain configured with failure cooldowns, and unsuccessful checks are never treated as an empty market. Home 4 Everyone and Smiley intermittently return a SiteGround CAPTCHA redirect with HTTP 202 from particular runners. The collector recognizes that response as blocked, never follows the challenge, and never treats it as empty inventory. These two sources recheck after 15 minutes without escalating to a day-long cooldown; other persistent access and certificate failures keep their exponential backoff. The validation report records the actual result from each run.

Successful bounded scans can still be partial: page/time limits, repeated pages, or ambiguous property types are reported. Explicit broker categories and card-specific fields determine type; individual units remain excluded, while an explicitly advertised whole family house with apartments remains eligible. Unknown building area remains unknown even when a card provides an unlabeled square-meter value. BHHS built-up size and Smiley property-size fields are used only when explicitly provided.

Partial-coverage improvements: Ben, Century 21, HKG and MPG fast scans have larger bounded page allowances; Ben/MPG page-one aliases are skipped. Ambiguous cards from Bluefin, Keller Williams and Home 4 Everyone receive at most two public description reads per fast scan or twelve per deep scan per source. Only verified listing-description sections determine type; navigation and related cards are excluded. Classification results are cached for seven days and unsuccessful/ambiguous reads for one hour, keyed by card content. Known commercial/residence exclusions do not count as unknown types. Expanded configurations establish a new coverage baseline before NEW alerts resume. Home 4 Everyone uses an 8-second connection timeout and 12-second read timeout with one transient retry and bounded scan budgets; its hosting CAPTCHA can still block individual runners.

Whole apartment-only properties are eligible without a separate house: an explicit multi-apartment offer such as “7 Studio Apartments in Moko”, or a property explicitly containing several apartments, is classified as Apartment Complex even when its broker category is Apartment. Numbered individual apartments, per-unit offers, remaining new-project units, and residence-project offerings remain excluded. The USD 650,000 total asking-price ceiling and unavailable-status filters still apply. This is a property selection preference, not confirmation of permission to occupy or modify any unit.

Commercial broker categories do not automatically exclude residential income properties: whole apartment buildings/complexes and houses offered together with apartments remain eligible. Aruba Happy Homes and Keller Williams commercial sale routes are included alongside their residential/land routes. Generic commercial cards may require a cached, bounded check of their verified listing-description section. Ordinary office, retail, warehouse, hotel and other nonresidential offers stay excluded, as do individual units, residence-project units, rentals, sold listings and asking prices over USD 650,000. Category expansion is baselined before new-listing alerts resume.
